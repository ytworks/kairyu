# GLM-5.3-Flash + Quyet: the verified tool route with GLM as the writer (2026-10-12)

Status: **draft, awaiting owner approval** (proposed VCO-D23). Branch:
`claude/glm-5.3-flash-quyet-8gpu`. GPU verification cannot run on the
planning machine; it is listed as remaining work in the draft PR.

## Context

`examples/deepseek-v4.1-quyet-8gpu` (VCO-D21/D22, PR #645) runs
DeepSeek-V4.1 DP6/EP6 on GPUs 0-5 as the writer and two Quyet-1.0-Large
replicas (GPU 6 route judge, GPU 7 judgments and form check) behind one
public model `kairyu-verified-tool`. `examples/glm-5.3-flash-6gpu` (PR #644)
serves official FP8 GLM-5.3-Flash on the same six GPUs as one TP2 x DP3 /
EP6 replica with MTP 3 on stock vLLM v0.31.0 and passes all nine gates.

Proposed scope:

1. New example `examples/glm-5.3-flash-quyet-8gpu`. The DeepSeek example
   stays as it is (it is the comparison baseline).
2. L1: GLM-5.3-Flash exactly as `glm-5.3-flash-6gpu` selected it (GPUs 0-5)
   replaces DeepSeek; the two Quyet replicas exactly as
   `deepseek-v4.1-quyet-8gpu` (GPUs 6, 7).
3. L2: `verified-tool.yaml` of the Quyet example with GLM in every writer
   role (candidates, answer and its fixes, think route). Routing, the Quyet
   questions, thresholds, states and budget are unchanged. Only what GLM
   forces changes (table below).
4. L3: one public model `kairyu-verified-tool`, Open WebUI.
5. `kairyu/` is not changed (checked below). Every script, test, dataset and
   setting is the new example's own; the two source examples are read as
   references only.

## Framework admission check (no framework change)

- Effort: roles with `reasoning_effort: inherit` send `reasoning_effort`
  (low / high / max after Kairyu's normalization, which the official GLM
  template accepts unchanged; `kairyu/engine/openai_backend.py`
  `_validated_request_payload`). The conductor adds `enable_thinking` only when the
  worker's pool allows that kwarg
  (`kairyu/orchestration/conductor.py` `_worker_chat_template_kwargs`); the
  GLM pool allows none, so no `chat_template_kwargs` reach GLM, and every GLM
  role declares an effort. The PR #644 limitation (legacy chat path rejects
  `chat_template_kwargs` on text) does not apply: the public model is an
  orchestrator, and its writer roles send none.
- The profile judge's `enable_thinking: false` only goes to a worker that
  allows it; the judge is Quyet over System One.
- Checklist verifiers, `foreach`, `max_questions_per_call`, `refine_prompt`,
  strict System One refusal -> `publish_unverified`, native conversation and
  the `<tool_call>` envelope are model-agnostic (m1 D8, m1 D9).

A CPU test asserts the dispatched GLM payloads (effort present, no
`chat_template_kwargs`) so a framework regression shows here, not on GPU.

Everything else in `verified-tool.yaml` is copied verbatim: candidate count
10-16, six judgments per candidate (32 per read), answer and refine prompts,
seven form questions at 0.5 in strict mode, at most two fixes, Quyet states
(route 12,000 chars, judgments 8,000, form 6,000), `prefer: TOOL >= 0.1`,
judge timeout 60 s with fallback to the think route, budget `max_steps` 10 /
`max_refine_depth` 2, `expose_intermediate_outputs: false`.

## Open decisions (owner)

1. **Default effort.** GLM's official default is `max`; DeepSeek-Quyet used
   `high` (DeepSeek's official default). PR #644 measured that at `low` and
   `high` GLM answers tool turns with thinking closed at once (13 tokens),
   so `high` may make the candidates and the answer non-reasoning on agent
   turns. Proposal: `max` (official-first), and the GPU run records TOOL
   route latency; if serving p50 at c16 exceeds the 900 s agent turn
   envelope, re-ask the owner before switching to `high`.
2. **Example name** `glm-5.3-flash-quyet-8gpu` (proposed).
3. **Datasets.** Copy `datasets/tool-routing-set.json` and
   `datasets/tool-turns.json` verbatim (proposed), so gate results compare
   one-to-one with DeepSeek-Quyet.

## Tests (CPU)

Per the test policy: test the accepted input and the observable result; no
tests that mirror static configuration.

- `test_gateway_builds_from_the_example_configs`: `kairyu.yaml` +
  `verified-tool.yaml` load and build the gateway (protects config/DSL drift).
- `test_compose_gpus_match_the_allocation`: GLM on 0-5, Quyet on 6 and 7, TP
  pairs as `dp_rank_gpu_ids` (a wrong device list starts on busy GPUs).
- `test_think_is_one_glm_answer_at_the_callers_effort` (parametrized over
  default/low/high/max): one GLM dispatch, `reasoning_effort` equals the
  caller's (or the default), **no `chat_template_kwargs`** (new GLM contract:
  an `enable_thinking` kwarg would change GLM's prompt or be refused).
- `test_tool_route_judges_candidates_then_checks_the_replys_form`: fake GLM
  and fake Quyet (refuses more than 32 questions): candidates -> 6 x n
  judgments -> answer -> form check, published reply carries a structured
  call, effort reaches candidates and answer.
- `test_a_reply_failing_the_form_check_is_fixed_and_checked_again`: fix then
  pass; two fixes then exhaustion publishes the last reply.
- `test_a_reply_too_long_to_check_whole_is_published_unverified`: strict
  refusal -> `kairyu_verification.guaranteed` false, reply published.
- `test_an_unavailable_route_judge_routes_to_the_think_answer`.

The L2 tests mirror the DeepSeek-Quyet file because each example owns its own
spec copy; the GLM-specific additions are the payload assertion and the
131,072-token cap. No tests are added for prompt text, port numbers or pins.

Checks before the PR leaves draft: `uv run ruff check .`, `uv run pytest
tests/unit/test_glm53_quyet_example.py tests/unit/test_frontier_examplectl.py`,
then the full CPU suite.

## GPU verification (remaining work; needs the 8 x RTX PRO 6000 host)

Before the gates (recorded in MEASUREMENTS): six turns from
`datasets/tool-turns.json` through the TOOL route: candidate count (>= 10),
JSON validity of GLM's `response_format` output with the `glm47` reasoning
parser and MTP, judgment read time and truncation, form verdicts and fixes,
batched replies. The 64-turn route replay is not repeated: the route judge
reads only the conversation, so its result is the DeepSeek-Quyet run's
(5/64).

| # | Gate | Pass | Budget |
|---|---|---|---|
| 1 | `l1` | every GLM DP engine (exact probes, effort render low/high/max, prefix-cache consistency with MTP, tool call, image); KV pool >= 1,048,576 per engine; System One on each Quyet replica; strict name refuses a cut state; one structured call from the public model | 15 min |
| 2 | `routing` | TOOL miss < 10 % on both halves; THINK precision >= 90 % | 30 min |
| 3 | `think-route` | everyday requests stream from the think route at the default effort | 30 min |
| 4 | `effort` | the caller's effort reaches the think route, candidates, answer and fixes; route judged on `quyet_route` | 90 min |
| 5 | `verified-tool-route` | 12/12 TOOL; >= 10 candidates; 6 x n judgments on `quyet_judge` (<= 32 per read); form check after the answer; structured call to a declared tool | 120 min |
| 6 | `fallback` | route replica down: THINK; judge replica down: TOOL published unverified with a call; both back: judged and form-checked | 60 min |
| 7 | `serving` | c1/c4/c8/c16 (8/16/16/32) all answered, every reply a structured call; latency, tokens per route | 40 min |
| 8 | `serving-routed` | routing set at the same levels, all answered; route mix and latency | 30 min |
| 9 | `browser` | Open WebUI answers | 5 min |

Comparison baseline: DeepSeek-Quyet run `20261011-r2` (verified-tool-route
12/12, serving p50 c1/c16 74.8/134.2 s, 0 Quyet states cut, 4 of 69 TOOL
replies at the fix limit).

GPU risks to watch:

1. Structured JSON (`json_schema`, 10-16 items) from GLM with the `glm47`
   reasoning parser and MTP 3 on vLLM v0.31.0: invalid or truncated JSON
   fails the candidates role.
2. Effort `max` latency on candidates (one call, up to 131,072 tokens).
3. GLM tool-call markup leaking into reply text (F2) at a higher rate than
   DeepSeek's DSML.
4. Host memory: GLM's six-GPU replica plus two Quyet replicas on one host
   (DeepSeek-Quyet minimum 256 GiB available).
