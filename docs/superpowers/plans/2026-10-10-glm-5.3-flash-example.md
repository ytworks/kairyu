# GLM-5.3-Flash single-replica example (four GPUs planned, six-GPU fallback)

Status: **Approved 2026-10-10 and implemented on the six-GPU fallback (`examples/glm-5.3-flash-6gpu/`); all nine gates pass (2026-10-11); see Outcome.**

Accepted scope (owner, 2026-10-10):

- One replica on four GPUs (GPUs 0–3). If the official checkpoint does not
  fit on four GPUs (fit rule below), the owner allows six GPUs: one DP6/EP6
  replica on GPUs 0–5, example `glm-5.3-flash-6gpu`.
- L2 and L3 are the `deepseek-v4.1-flash-6gpu` structure: one public model
  backed by one `ReplicaPool` replica, the OpenAI-compatible API, and Open
  WebUI. No orchestration DAG, no judge, no second model.
- `kairyu/` is not changed. Every script, test and setting is this
  example's own; sibling examples are read as references only.
- Fresh branch `claude/glm-5.3-flash-example` from `main`; separate PR.
- "Optimal" means: start from the official settings, deviate only where
  this hardware forces it or a bounded measurement shows a gain, and write
  down every deviation with its reason.

Example directory: `examples/glm-5.3-flash-4gpu/`. Ports: API 8015,
Chat UI 3016 (both unused). The Chat UI and API bind 0.0.0.0 and the
printed URL uses `PUBLIC_HOST` (newer example convention).

## Fit rule (decides four or six GPUs, before the example is written)

The official checkpoint fits on four GPUs when stock v0.31.0 with the
baseline command below and MTP off meets all three:

1. starts at `--gpu-memory-utilization` ≤ 0.95;
2. reports a KV pool ≥ 1,048,576 tokens;
3. runs with `--max-num-seqs 16`.

Otherwise the example becomes one DP6/EP6 replica on GPUs 0–5
(`glm-5.3-flash-6gpu`), with the same L2/L3 and gates. Time box for the fit
probe: 0.5 GPU day. The numbers are reported and work continues.

## L1 plan (vLLM on GPUs 0–3)

Baseline command (every flag traceable to the table above):

```
--tensor-parallel-size 4
--kv-cache-dtype fp8
--max-model-len 1048576 --max-num-seqs 16 --max-num-batched-tokens 8192
--gpu-memory-utilization <measured, <= 0.95> --enable-prefix-caching
--reasoning-parser glm47 --tool-call-parser glm47 --enable-auto-tool-choice
--limit-mm-per-prompt '{"image":8,"video":0}'
--served-model-name glm-5.3-flash
env: VLLM_ENGINE_READY_TIMEOUT_S=3600, PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True, HF_HUB_OFFLINE=1
```

Deviations only where a measurement requires them, each recorded in
`MEASUREMENTS.md` (for example `--no-enable-flashinfer-autotune`, the
recipe's own Hopper flag, if autotuning stalls). A vLLM code patch or an
overlay image is not applied on my own: work stops and the owner decides.

Tune (`tune.py`, one flag at a time, time box 1 GPU day):

- MTP k = 3 and k = 5. Adopted only if (a) the fit rule still holds,
  (b) correctness: exact `323` probes and batched prefix-cache-hit requests
  give the same answers as MTP off, with no corrupted output (precedents:
  vllm#53912 corrupted prefix-cached MTP output on hybrid GDN in
  `qwen3.8-flash-next-dp2-8gpu`; #53963 reports MTP instability on SM120),
  and (c) the selection rule. Otherwise MTP stays off.
- All-reduce: NCCL vs FlashInfer PCIe IPC.
- `--max-num-batched-tokens` 8192 vs 4096 vs 16384.
- `--mm-encoder-tp-mode data` vs default (image TTFT).
- `--max-num-seqs` 16 vs 32, if memory allows.
- Finally pin `--kv-cache-memory` (lesson from `qwen3.8-flash-next-dp2-8gpu`:
  a cold compile cache shrank the KV pool).

Selection rule: ≥ 5 % gain on c1 or c16 with no > 5 % loss elsewhere;
a repeated baseline sizes the noise.

## Outcome and deviations from this plan

- Fit probe, four GPUs (TP4, stock v0.31.0, 0.95, MTP off): weights 76.8 GiB
  and CUDA graphs 4.28 GiB per GPU left 1.81 GiB of KV memory; a 1,048,576-token
  request needs 7.56 GiB (vLLM: maximum length 235,008). Rule 2 fails; graphs
  off would still leave 6.1 GiB. Four GPUs do not fit.
- Six-GPU fallback (owner-approved): one DP6 / EP6 replica on GPUs 0-5.
  Weights 64.76 GiB per GPU (routed experts 283.6 GiB split six ways; 14.4 GiB
  of attention, KDA, shared and dense weights plus the 1.05 GiB vision encoder
  replicated). At 0.92 the KV pool was 0.61 GiB short of one full context
  (966,144 tokens); at 0.95 each engine has 10.29 GiB of KV, 1,347,016 tokens
  (1.28 full contexts), 16 sequences per engine: all three rules hold.
  Readiness passed (exact `323` from every DP rank, a tool call, a red image).
- Directory, storage and test file are named `glm-5.3-flash-6gpu`; Kairyu
  admits 96 requests (6 engines x 16); the serving rows are c1/8/16/32/64 x 64
  as in `deepseek-v4.1-flash-6gpu`; the TP4-specific tune candidates
  (all-reduce, encoder TP mode, TP4 + EP4) are replaced by TP2 x DP3.

- Tune (one flag at a time, three runs; `MEASUREMENTS.md`): MTP does not fit
  beside a 1M KV pool on DP6; TP2 x DP3 at equal capacity (3 x 32 = 96) beats
  DP6 (+12 % / +11 % at c1 / c16) and doubles the KV pool; MTP on TP2 needs
  NCCL (`--disable-custom-all-reduce`: the custom all-reduce fails in the
  drafter's CUDA-graph capture); MTP 3 doubles c1 (74 tok/s), MTP 5 loses 6 %
  at c16; batch 4K loses 11 % at c64, batch 16K leaves no 1M pool. Selected:
  TP2 x DP3 / EP6, 32 sequences per engine, MTP 3, NCCL, KV pinned at
  16.75 GiB per GPU (2,028,392 tokens per engine).
- Final gates run `20261011-r1` failed three checks, each changed with the
  owner's approval: the Chat UI's `clear_thinking` (Kairyu's legacy chat path
  rejects `chat_template_kwargs` on text requests; the filter now sends only
  the effort), reasoning text required at low/high effort (GLM may skip it;
  now required only at default/max), and the exact-text long-context check
  (now: the answer names exactly the planted key). Run `20261011-r2` passes
  all nine gates.
